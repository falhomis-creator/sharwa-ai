# عقد أحداث سلة المتجر — POST /webhooks/platform/cart

**الجمهور:** فريق منصة المتجر (sharwa_saas) الذي سيُرسل أحداث السلة إلى Sharwa-AI core.
**الحالة:** المستقبِل مبنيّ ويعمل (P3.2). **التذكير نفسه مُظلَم حتى إشعار آخر**: لا رسالة تُرسَل لأي عميل من هذا المسار اليوم، لكن الأحداث تُخزَّن والوظائف تُجدوَل، فحين تُفتح الإضاءة (P3.3+/P3.4 بموافقة المالك) ينطلق التذكير بلا تغيير في العقد.
**نطاق هذا المستند:** العقد الحرفي بين المرسِل والمستقبِل. كل ما ليس هنا لا يُضمن.

---

## 1. نقطة النهاية والقيود

| البند | القيمة |
|---|---|
| المسار | `POST /webhooks/platform/cart` |
| نوع الجسم | `application/json` (UTF-8) |
| الحدّ الأقصى للجسم | `PLATFORM_WEBHOOK_BODY_MAX_BYTES` (افتراضي 262144 بايت) — الأكبر ⇒ `413` |
| الحدّ الأقصى للدفعة | `PLATFORM_EVENT_BATCH_MAX` حدثاً (افتراضي 1000) — الأكبر ⇒ `422` |
| نافذة إعادة التشغيل | `PLATFORM_TIMESTAMP_SKEW_S` ثانية (افتراضي 300) — الأقدم ⇒ `401` |
| المصادقة | HMAC-SHA256 (لا JWT، لا توكن في الجسم) |

## 2. الترويسات الإلزامية

| الترويسة | المعنى |
|---|---|
| `X-Platform-Timestamp` | ثواني Unix (UTC) لحظة الإرسال. تُوقَّع وتُفحص نافذتها |
| `X-Platform-Signature` | سداسية hex لـ `HMAC-SHA256(secret, f"{timestamp}." + raw_body)` |

`secret` هو `PLATFORM_WEBHOOK_SECRET` — **مستقلّ تماماً** عن أي سرّ آخر في المنظومة (الجيتواي، الـAPI…). قيمة فارغة في المستقبِل ترفض الإقلاع. مثال توقيع (Python):

```python
import hmac, hashlib, json
ts = "1760000000"
body = json.dumps(payload).encode()
sig = hmac.new(SECRET.encode(), f"{ts}.".encode() + body, hashlib.sha256).hexdigest()
```

**ترتيب الفحص في المستقبِل (حرفي):** حدّ الحجم ⇒ التوقيع ⇒ النافذة الزمنية ⇒ تحليل JSON ⇒ المخطّط. لا يُقرأ جسمك قبل اجتياز التوقيع.

## 3. مخطّط الجسم

```json
{
  "tenant_ref": "store-123",
  "events": [ { "...حدث واحد...": "انظر 3.1/3.2" } ]
}
```

- `tenant_ref` (نصّ، إلزامي): `platform_ref` الخاص بالمتجر كما سُجِّل عند إنشاء المستأجر. مجهول/معلَّق ⇒ `200 unknown_tenant_ignored` (سلوك حسن النية: لا تعد الإرسال).
- `events` (مصفوفة، إلزامية): تُطبَّق بالترتيب، كلٌّ في معاملته المستقلة.

### 3.1 `cart.updated`

```json
{
  "type": "cart.updated",
  "cart_id": "987654321",
  "occurred_at": "2026-10-04T12:30:05Z",
  "customer": { "wa_id": "967712345678" },
  "item_count": 2,
  "total_minor": 5000,
  "currency": "SAR",
  "items": [ {"title": "قميص قطن رجالي"}, {"title": "بنطال جينز"} ]
}
```

| الحقل | القاعدة |
|---|---|
| `type` | أحد: `cart.updated` · `cart.recovered` · `cart.cleared` |
| `cart_id` | نصّ، 1..64 حرفاً، معرّف السلة عند المنصة |
| `occurred_at` | ISO-8601 (تُقبل لاحقة `Z`)؛ ساذج يُقرأ UTC |
| `customer` | كائن فيه **واحد على الأقل**: `wa_id` (أرقام بصيغة واتساب بلا `+`) أو `phone_e164` (E.164 مع `+`) |
| `item_count` | عدد صحيح ≥ 0 |
| `total_minor` | عدد صحيح ≥ 0 (بالوحدة الصغرى للعملة: هللات/سنتات) |
| `currency` | نصّ بطول 3 بالضبط (ISO-4217) |
| `items` | مصفوفة ≤ 3 عناصر، كلٌّ كائن بحقل `title` نصّي (يُقصّ إلى 60 حرفاً) |

### 3.2 `cart.recovered` / `cart.cleared`

```json
{ "type": "cart.recovered", "cart_id": "987654321", "occurred_at": "2026-10-04T14:02:11Z" }
```

حدثان **نهائيان**: `recovered` (اكتمل الشراء/استُعيدت السلة) و`cleared` (فُرِّغت/أُلغيت). لا حقول إضافية مطلوبة.

## 4. الدلالات (الترتيب · التكرار · النهائية)

1. **الهوية صارمة:** العميل يُطابَق بـ`wa_id` ثم `phone_e164` ضمن متجر الإرسال فقط. **لا مطابقة ⇒ الحدث يُحصى `ignored_no_customer` ويُتجاهل** — لا يُنشأ عميل أبداً، ولا تُحفَظ سلة.
2. **الزمن رتيب:** `last_activity_at` للسلة = الأحدث بين الوارد والقائم (`GREATEST`). حدث **أقدم** يصل متأخراً لا يُرجِع الزمن للوراء ولا يؤخّر التذكير خطأً.
3. **النشاط يؤجّل:** كل `cart.updated` بطابع أحدث يحدّث السلة **ويدفع موعد التذكير** (`run_at = آخر نشاط + CART_REMINDER_DELAY_H`).
4. **التكرار آمن:** إرسال الحدث نفسه مرّتين لا ينشئ وظيفة ثانية ولا يحرّك الزمن (مفتاح التكرار `cart:{cart_id}:stage1` فريد في القاعدة).
5. **النهائية تغلب:** `recovered`/`cleared` يغلقان السلة **ويفسخان الوظيفة المجدولة في المعاملة نفسها**، حتى لو سبقا موعد التذكير. السلة النهائية **لا تُفتح من جديد** بأي `cart.updated` لاحق؛ والسلة التي ذُكِّرت (`reminded`) لا تُجدوَل ثانية (مرحلة واحدة).
6. **أنواع مجهولة:** نوع غير معروف لا يفشل الطلب — يُحصى (`unknown_type`) ويُسجَّل اسم النوع مرّة واحدة. استعملها للتوسعة المستقبلية بصيغة لا تكسر القديم.
7. **مفاتيح غير معروفة** داخل حدث معروف: **تُتجاهل ولا تُخزَّن** (انظر §6).

## 5. الاستجابات ورموز الأخطاء

| الحالة | المعنى |
|---|---|
| `200` + `{"status":"accepted","counts":{...}}` | دفعة سليمة؛ `counts` يحصي النواتج (`applied`/`ignored_no_customer`/`already_final`/`already_reminded`/`unknown_type`) |
| `200` + `{"status":"unknown_tenant_ignored"}` | المستأجر مجهول أو معلّق — **لا تعد الإرسال** |
| `401` `PLATFORM_SIGNATURE_INVALID` | التوقيع خاطئ/ناقص — أصلح التوقيع ثم أعد |
| `401` `PLATFORM_TIMESTAMP_SKEW` | الطابع أقدم من النافذة — أعد بطابع حاليّ |
| `413` `PLATFORM_PAYLOAD_TOO_LARGE` | الجسم فوق الحدّ — قسّم الدفعة |
| `422` `VALIDATION_FAILED` | JSON فاسد أو مخطّط خاطئ (راجع §3) — أصلح ثم أعد |

**إعادة المحاولة:** أعِد فقط على أخطاء الشبكة وعلى 5xx. أخطاء 401/413/422 أخطاء إرسال يجب إصلاحها؛ إعادة إرسالها كما هي ستفشل دائماً. الأحداث **idempotent** (§4.4) فالإعادة بعد انقطاع آمنة.

## 6. ما **لا يجوز** إرساله أبداً

هذا عقد **إشارة نشاط**، لا قناة بيانات. المرسِل لا يُرسل:

- **نصوصاً حرّة** من أي نوع (رسائل، ملاحظات، تعليقات العميل…) — لن تُخزَّن ولن تظهر في أي تذكير؛ نصّ التذكير يأتي من قالب معتمد عندنا فقط.
- **بيانات دفع أو بطاقات أو عناوين شحن أو فواتير** — لا حقل لها في المخطّط، وأي مفتاح غريب يُهمَل ولا يُخزَّن.
- **بيانات شخصية** خارج حقلي الهوية المسموحين (`wa_id`/`phone_e164`): أسماء، إيميلات، مواقع جغرافية.
- **أكواد خصم أو هويات جلسات أو توكنات** — ليست من هذا العقد.

اللقطة المخزَّنة عندنا **صغرى بحكم التصميم**: عدد القطع، المجموع، العملة، وحتى 3 عناوين مقصوصة (60 حرفاً) — تُحذف بعد `CARTS_RETENTION_D` يوماً من إقفال السلة، ولا تُطبع في أي سجلّ.

## 7. دورة الحياة عندنا (للفهم، لا للتطابق الحرفي)

`cart.updated` ⇒ حفظ لقطة + وظيفة `cart_reminder` مجدولة بعد 24 ساعة من آخر نشاط (قابلة للضبط) ⇒ عند الموعد يتحقق المحرك: السلة ما زالت مفتوحة؟ العميل له محادثة؟ القالب مُسجَّل؟ — ثم يمرّ أي إرسال ببوّابة سياسة منفصلة (موافقة، سقوف تكرار، ساعات هدوء…). حدث نهائي أو غياب أحد الشروط ⇒ إلغاء موثَّق السبب، لا رسالة.

## 8. تشغيل المرسِل (خلاصة تنفيذية)

1. اجمع الأحداث في دفعات، رتّبها بترتيب حدوثها، وأرسلها عند حدوثها (لا تنتظر دورة).
2. وقّع كل طلب: `sig = HMAC_SHA256(secret, "{ts}." + body)` واضبط الترويستين.
3. عند الفشل بشبكة/5xx: أعد بتراجع. عند 401/413/422: أصلح السبب (لن ينجح الإعادة كما هو).
4. أرسل `cart.recovered`/`cart.cleared` فور العلم بهما — هما ما يمنع أي تذكير لاحق.
5. لا تخترع حقولاً؛ ما ليس في §3 لا يُقرأ.
