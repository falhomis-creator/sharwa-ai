## 1. القرار التقني
واجهة **بلا خطوة بناء**: HTML + CSS + ES modules (عربي RTL) تُقدَّم من الـAPI نفسه على `/console/` عبر `CONSOLE_STATIC_DIR`. السبب: أداة تُشغِّل تسويقاً حقيقياً لا تمرّ عبر مئات حزم npm (سطح سلسلة التوريد)، ولا CORS، ولا Node على جهاز المالك، وأمر تشغيل واحد. CSP صارمة (لا inline، لا مضيف خارجي) و`no-store` و`X-Frame-Options: DENY`؛ البيانات تُرسَم بـ`textContent`؛ الرمز في `sessionStorage` فقط.

## 2. ما سُلِّم (VERIFIED على PG16+Redis حقيقيين)
- **API** (`routes_marketing_admin.py`، موثَّق في `docs/ADMIN_DASHBOARD_API.md`): قائمة المستأجرين، تفاصيل مستأجر (فحص تمهيدي + قنوات + سجلّات)، مؤشرات المنصّة، `enable`/`disable`/`set-cap`، ومساران قراءة-فقط للتاجر (`/v1/marketing/overview|metrics`).
- **الأمان (H104، بقرار المالك: الواجهة الرسومية مسموحة):** مسارات المدير `platform_admin` حصراً؛ مستأجر الهدف من المسار لكنّ كل وصول بعده داخل `tenant_tx(target)` **تحت RLS** بدور `sharwa_app`؛ القراءة العابرة الوحيدة دالة `SECURITY DEFINER` (ترحيل 0018 `app.admin_list_tenants`، خمسة أعمدة معرِّفات، لـ`sharwa_system` فقط — مُثبَت: دور التطبيق يُرفض والدور النظامي لا يقرأ `tenants` مباشرة). التفعيل بنفس بوّابات الـCLI (عبارة حرفية + فحوص + سبب)، الفاعل `dashboard:<sub من JWT>`، وكل تغيير في `audit_log` + السجلّ الإلحاقي بمعاملة واحدة، والمحاولة المرفوضة تُدقَّق ولا تُطبَّق.
- **بنية:** منطق مشترك محايد `app/marketing_ops.py` (لا يستورد workers ولا api) فلا تُضاف أي مخالفة import-linter؛ الحقائق التي ترى طبقةُ العمّال وحدها تُحقَن عند الإقلاع (`MarketingEnv`). رمز خطأ جديد `PRECONDITION_FAILED` (412) مع `details.failed` من المفردات المغلقة، وحُدِّث عقد الكونسول المجمَّد.
- **الواجهة:** المستأجرون (جدول + المفتاح العام)، صفحة مستأجر (قائمة ✓/✕ للفحص، قنوات، معاينة، سجلّ، تفعيل/إيقاف/سقف)، المؤشرات (رسائل يومية مكدَّسة، اشتراكات/إيقافات، حالات السلال ونسبة الاسترجاع، عرض جدولي، تلميح عند المرور)، شاشة التاجر، وضع داكن وجوال.
- **التشغيل المحلي:** `scripts/dev_console.py` (يرفض قاعدة غير محلية) يبذر أربعة مستأجري `demo-*` **كلهم مُطفأ** ويولّد مفتاح RSA مؤقتاً وتوكنين؛ التعليمات في `frontend/README.md`.
